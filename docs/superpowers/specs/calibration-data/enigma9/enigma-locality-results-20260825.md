## 遠い罠3手番の帯残存チェック

`enigma13_off_run1.json` の白手から `selected != ai_top` かつ `cheb(selected, ai_top) >= 5` かつ `point_loss >= 1.0` を

個別 `--move N` 実行（OFF と ON(σ3)）の結果（E は各アームの実クエリ由来・別プロセスなので `--batch` の値とは一致しない）:

| move_num | OFF 選択(E) | ON(σ3) 選択(E) | ON `Band:` | 遠い罠は帯に残ったか |
|---:|---|---|---|---|
| 72 | A6 (E=2.79) | A8 (E=2.86, prox=0.00) | `Band: 1 within slack 0.30` | 残った（band=1件のみで、遠い候補がそのまま単独選択） |

3手番とも `Band:` サイズが1（top net 付近の他候補が slack 0.30 以内に無い＝局所性オプションが介入する対象そのものが存在しない）で、
遠くても net が明確に頭一つ抜けている「本物の罠」は ON でも素通しで選ばれている。**σ3 は近接候補が拮抗しているときにだけ近い方へ寄せる設計どおりに振る舞い、
E>=1 の孤立した遠い罠を握りつぶしてはいない**（ただし各手番1プロセスずつの単発実測＝KataGo の run 間分散があるので、この3件で汎化を主張しない）。

move72 では OFF/ON で選択手自体が A6→A8 と変わっているが、これは局所性の効果ではなく候補プールの net 順位が僅差
（A8 net=4.00 vs A6 net=4.62 の OFF 側の差が、ON 側では A8 net=3.64 vs A6 net=1.93 に逆転）で、別プロセスの探索ノイズによる
入れ替わりと見るのが妥当（CLAUDE.md「humanPolicy を run 間で決定的な値として扱わない」と同種の分散）。

損失を悪化させている方向**が出ている。19路は1run のみのため run間分散との切り分けができず、**方向確認に留め校正は未実施**。

## 判定（spec §7「採用判断」）

- **距離分布の改善**: 13路は off→s3・off→s4 のどちらも `>=4`（対 opp_last・対 ai_top）が一貫して減少し、run間ノイズの範囲を超える差。改善方向は確定。
- **損失側 (c)**: `mean_ptloss` の3run平均は off 1.739 → s3 1.710（閾値内＝実質不変）→ s4 1.780（off比 +0.041 は閾値内だが、s3比 +0.070 は閾値超え＝s4はs3より明確に悪い）。`total_loss` も s3(85.51) < off(86.93) < s4(88.99)。**σ3 は損失を悪化させていないが、σ4 は s3 より損失側で劣る。**
- **E>=1 の遠い罠の残存 (d)**: 抽出した3件の遠い罠（point_loss 5.9〜7.4・cheb 5〜10）は σ3 の ON でも全件 `Band: 1`（介入対象外）でそのまま選択され続けた＝σ3 は本物の罠を握りつぶしていない。
- **`ai_top_move` 一致率**: off→s3 は +0.053（実差・一致率わずかに上昇）、off→s4 は +0.027（ノイズ境界）。一致率の変化自体は本オプションの直接目的ではないが、悪化はしていない。

**総合**: 13路は σ=3.0 を推奨する。距離分布の改善幅（`>=4` 対 ai_top: off 25.33→s3 18.00, −29%）が σ4（→20.00, −21%）より大きく、
かつ損失側（`mean_ptloss`・`total_loss`）が off 同等〜やや良好（s4 は損失側で off よりわずかに悪化方向）で、遠い本物の罠も保持されている。
σ4 は距離縮小効果がσ3よりやや弱く損失もやや高いため、13路の既定候補としてはσ3を優先する。

19路は σ5 の1run実測で `>=4`（対opp_last）縮小の方向は出たが `mean_ptloss`/`total_loss` の悪化がノイズ閾値を大きく超えて出ており、
**19路は方向確認のみで未校正**。複数run・複数σでの校正が必要（本タスクのスコープ外）。

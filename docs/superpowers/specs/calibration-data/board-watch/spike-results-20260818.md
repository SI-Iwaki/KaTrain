## 「2枚の差が相手の1手ぶん」が NG だった理由

`--save tests/data/board_watch_after.png` を実行したのは `before` 実行から数分後（このスパイクの Step 2 と Step 3 の間にレポート作成・コーディネータとの往復が挟まった）。その間に盤は1手ではなく2手分（白の応手＋黒＝アプリAIの再応手）進んでいた:

- before: 黒1子（`grid[4][5]`）のみ。**棋譜表示バーに「1. 黒4-5」と表示されており**（after の「3. 黒6-6」と同じUI要素・同じ位置）、手数1は画面から直接読み取れる（石数からの推測ではない）
- after: 黒2子・白1子。棋譜表示「3. 黒6-6」＝3手目まで進行済み
- 新規セルは2つだけ（プログラムで diff 済み）:
  - `row=3 col=3`: `.` → `B`（3手目・黒・最終手マーカーあり＝**アプリAI(KaasanBot)の着手**）
  - `row=4 col=3`: `.` → `W`（2手目・白＝**人間(Sithle)の着手**）
- 取られた石はなし（`W` は2手目、盤上に残っている）
- **経過時間の直接証拠**: 画面左上の時計が before「22:12」→ after「22:14」、Sithle（白番・人間）の残り時間が before「02:43」→ after「00:57」と、いずれも両スクリーンショットの同じUI要素で確認できる。この時間差の間に人間の着手（2手目・白）とアプリAIの応手（3手目・黒）の両方が行われたと考えられる

これは「相手が1手だけ打った」を確認する狙いのペアとしては**成立していない**（コーディネータの事前指示どおり、石2個以上の差はそのまま正直に報告し、きれいな1手差ペアを捏造しない）。ただし認識器そのものの動作（rect/size/石分類/マーカー）は before・after の両方で独立に検証でき、どちらも問題なし。この2枚を Task 13 の回帰テストに使う場合は、**「1手ぶんの差」の回帰には使えない**（実際の差は2手ぶん）ことに注意。回帰テストとして有効に主張できるのは:
- 各キャプチャ単体の rect/size/grid が期待値と一致すること
- 最終手マーカーが乗った石が `.` に化けないこと（before の黒1子、after の黒3手目の両方で確認済み＝**黒マーカーのサンプルのみ**。白石にマーカーが乗るケースは今回のペアでは検証できていない）

## 判定

- [x] 既存の認識器がそのまま使える → Task 2 へ進む
- [ ] 最終手マーカーで石が "." に化ける → 設計どおり §2.5(c) の進捗ウォッチドッグが要る（Task 6 で実装）。
      加えて board_watch 専用の分類関数が必要かをここで判断する（**詰碁経路の関数は変更しない**）
- [ ] 盤が検出できない → 設計の前提が崩れる。ここで止めてユーザーと相談する

認識器（`find_window_rect` / `capture_screen_rect` / `detect_board` / `detect_size_and_classify`）は今回の対局アプリの盤面に対してそのまま通った。board rect・盤サイズ・石の分類・最終手マーカーの4項目すべて OK。Task 2 以降は既存認識器をそのまま使える前提で進めてよい。

**このペア（`board_watch_before.png` / `board_watch_after.png`）が回帰用に保証する範囲**:
- カバーする: 9路盤・黒石/白石混在・最終手マーカーつきの**黒石**が正しく `B` と読める・盤面の一部だけに石がある疎な局面
- カバーしない: 差分が「相手の応手ちょうど1手ぶん」であること（実際は2手ぶん進んでいる）／白石に最終手マーカーが乗るケース／盤上の石が密集した局面／取られた石があるケース（capture）／13路・19路盤

**追加の発見（設計上の注意点）**: このマッチアップ（vs `:KaasanBot`）では**アプリAIが黒番、人間(`Sithle`)が白番**だった。Task 2 以降で「アプリAIの着手を検出する」ロジックを組むときに色を固定で仮定しない（対局ごと、あるいはアプリ側のマッチメイキングで手番の色が入れ替わりうる）。今回は対局者アイコンの色（黒丸/白丸）と着手履歴バーの「黒/白」表記から色を判別した。

# 観戦用の盤面反映モード 設計

日付: 2026-11-15 ／ 状態: 設計（未実装）

## 1. 目的

プロ同士の対局を観戦しながら、その盤面を KaTrain に取り込み、優劣（勝率・目差）と各手の分析を
リアルタイムで見られるようにする。いまの盤面監視（`board_watch.py`）は「KaTrain の AI 対 人間」専用で、
黒白とも画面から来る観戦は対象外（board-watch spec 追記12）。

## 2. ゴール／やらないこと

ゴール:

- 観戦中の盤面を途中からでも取り込み、以後は黒白どちらの着手も自動で反映する
- 自動反映はいつでも ON/OFF でき、OFF の間は手動で「今の盤面を反映」できる
  （1手に1時間かかる対局で監視を回し続けない）
- 観戦中は AI 戦略を一切走らせない。KaTrain 標準の解析（複数の候補手・勝率・目差）だけを使う
- ルール・コミ・アゲハマを途中からでも手で入力できる。野狐は画面から自動で読む
- 対応盤はいま読めるもの（野狐 PC 版・BlueStacks 上の黄盤／木目盤）だけ
- 将来ほかの盤に広げるための継ぎ目だけ用意する（検出器は作らない）

やらないこと:

- 新しい盤種の検出器、持ち時間・対局者名の読み取り、終局・投了の検出
- 既存の対局監視（kind=`game`）と詰碁監視（kind=`tsumego`）の挙動変更

やってはいけないこと（技術的に動いても失敗）:

- `reconcile` の判定順を緩める（「AI の手番なら注入しない」は色の取り違えに対する安全弁）
- 観戦中に AI が着手する／輪・カーソル・応手先読みが動く
- 推定で並べた手順を、確定した手順と区別なく見せる

## 3. 方式（検討した3案）

| 案 | 内容 | 判断 |
|---|---|---|
| A. 3つ目の監視種別 `spectate` | `BoardWatcher`・`AppBoardReader` を使い回し、判定だけ観戦用の純関数を別に足す | **採用**（ユーザーは作り方を一任＝設計者の判断） |
| B. 既存の対局監視を緩める | 「両者が人間なら観戦」として `reconcile` に分岐を足す | 不採用。安全弁の判定順と混ざり、対局監視を壊す危険がある |
| C. 変化のたびに局面を丸ごと取り込み直す | 手順を持たず最新局面だけ解析 | 不採用。各手の分析・形勢グラフが残らず目的に合わない |

## 4. 使い方（ユーザーから見た動き）

1. 観戦画面を開き、ホットキー（既定 `ctrl+alt+w`・設定 `board_watch.spectate_hotkey`。
   `Theme.KEY_*` と重ならないことを実装時に確認し、重なるなら別のキーにする）を押す
2. KaTrain が盤面を取り込み、両者を人間にして解析モードに入る。盤の上に観戦用の操作の帯が出る（既存の
   `board_watch_status` バナーとは別の行。警告はこれまでどおりバナーに出る）:

```
[観戦中 85手目] [自動反映 ●ON] [今すぐ反映] [対局情報…] [終了]      中国ルール コミ7.5
```

3. `自動反映` を OFF にすると画面の読み取りを止める（観戦セッションは残る）。`今すぐ反映` で1回だけ読む
4. `対局情報…` でルール・コミ・アゲハマ（黒が取った数／白が取った数）を編集できる。開始時にも自動で
   読めなかった場合だけ開く
5. `終了` またはホットキーの再押下で観戦を終え、対局者設定（人間／AI と戦略）を開始前に戻す

過去の手に戻って検討している間に新しい手が来ても、表示位置は動かさない（本譜の末尾に足すだけ）。
本譜の末尾を見ているときだけ表示も進む。

## 5. 設計

### 5.1 同期の判定（純関数・`board_watch.py`）

`spectate_sync(tip_grid, observed, to_play, last_mover, app_move_number, tip_move_number)` を新設する。
`reconcile` は変更しない。戻り値:

| 種別 | 条件 | 動作 |
|---|---|---|
| `in_sync` | 観測＝本譜末尾の盤 | 何もしない |
| `moves` | 増えた石を「`to_play` から黒白交互・最後は `last_mover` の色の石」の順に並べて再生すると観測に一致する | その手順を末尾へ追記。2手以上なら「順序は推定」と記録 |
| `reimport` | 上で説明できない（石が消えている・交互にならない・パスがある・盤サイズが違う・野狐の手数と合わない） | 観測局面を配置として取り込み直す |

- 複数手の順序: 最後の1手は直前手の印（`last_mover_color`）で確定、それ以外は同色内の順序が分からない
  ので任意（走査順）。再生結果が観測と一致することだけは必ず確かめる。推定で足したノードには
  コメント「順序は推定（自動反映 OFF の間の N 手）」を付け、バナーにも1回出す
- 野狐は窓タイトルの `[85手目]` を Win32 で読み（文字認識は不要）、`tip_move_number + 追記手数` と
  合わなければ `reimport` に倒す。読めない盤では `None`＝この検算を飛ばす
- 確定は既存と同じ `stable_frames`（2周同じ観測）。石を置くアニメーションの途中を拾わない
- `reimport` で前の手順は消える。直前の棋譜は消す前に自動保存しない（KaTrain の通常の新規対局と同じ）が、
  バナーに「手順を追えなかったため局面を取り込み直しました」と出す

### 5.2 監視ループ

`BoardWatcher` を使い回す。観戦用に必要な差分:

- 判定を差し替える。実装は `BoardWatcher` のサブクラスが 1 周ぶんの処理（`step`）だけ上書きする形にし、
  `BoardWatcher` 本体は変更しない＝既存の2種別はビット単位で同じ動き
- アプリ側が本譜の過去の局面を表示している（野狐の ◀ ボタン・変化図）ときは何もしない。棋譜を消して
  取り込み直さない。取り込み直しは通常周期で 2 周続いたときだけ確定する
- 自動停止（`auto_stop_sec`）と停滞警告（`stall_warn_sec`）は無効。長考は正常
- 周期は 1000ms 固定（`board_watch.spectate_poll_ms`）。着手らしき差を見た周だけ既存の低遅延周期で確定を待つ
- 連続対局の検出・対局者アイコンの色判定・`on_ahead`（輪・カーソル）・応手先読みは渡さない
- 自動反映 OFF＝監視スレッドを止める。`今すぐ反映`＝読み取り1回＋同じ判定＋同じ反映経路

### 5.3 KaTrain 側（`__main__.py`）

- `_board_watch_kind = "spectate"` を追加。開始時に両者を人間にし（元の設定は覚えて終了時に戻す）、
  解析モードにする。取り込みは `_do_board_watch_start` と同じ `board_sgf` 経路（手番は `last_mover_color`）
- 反映は新メッセージ `board-watch-spectate-append`（手順のリスト・期待する末尾の手数つき）。
  セッションが持つ「本譜末尾ノード」に子を足して解析を発行する。`current_node` が末尾のときだけ進める。
  ユーザーが途中に作った変化には触らない。末尾の手数が期待と違えば捨てる（既存の注入と同じ再検証）
- 既存の監視が動いていたら止めてから始める。観戦中に `ctrl+alt+d`（対局監視）を押したら観戦を終えてから始める
- 新規対局・SGF 読み込みなどでゲームが作り直されたら観戦は終了する

### 5.4 対局情報（ルール・コミ・アゲハマ）

- 入力欄: ルール（日本／中国ほか KaTrain の一覧）、コミ、黒のアゲハマ、白のアゲハマ。既定は
  `game/rules`・`game/komi`・0／0
- 反映: ルールとコミは root に書き、解析をやり直す。アゲハマは KataGo に渡す口が無いので、
  **地を数えるルール（日本など）のときだけコミに畳む**: エンジンに渡すコミ＝コミ＋（白のアゲハマ−黒のアゲハマ）。
  画面に出すコミは元の値のまま、対局者欄の取り石数には入力値を足す。面積を数えるルール（中国など）では
  アゲハマは結果に影響しないので表示だけ
- **入力欄のアゲハマは「アプリにいま出ている累計」**（画面の数字をそのまま入れられる＝設計者の判断）。
  内部では「取り込み時点の分＝入力値−取り込み後に KaTrain が数えた取り石」に直して持つ。これで途中で
  開いて今の数を入れても二重に数えない。欄を開いたときの初期値は「取り込み時点の分＋KaTrain が数えた分」
- `reimport` のたびにアゲハマは読み直す（野狐）。読めない盤ではその時点の累計（上の初期値）を引き継ぎ、
  「アゲハマを確認してください」と出す
- **手番の決め方（設計者の判断）**: 直前手の印 → 読めなければ野狐の `[N手目]` の偶奇（奇数＝黒が打った直後。
  置碁は考えない）→ どちらも無ければ、開始時は対局情報の欄で「次の手番」を聞く。自動反映の途中の
  `reimport` では欄を開かず、直前の本譜末尾の手番から交互が続くと仮定して「手番を確認してください」と出す
  （対局情報の欄に「次の手番」を常に置き、後から直せる）
- 野狐の自動読み取り: Windows 標準の文字認識（`Windows.Media.Ocr`・日本語）で対局者パネルを読む。
  **実測 2026-11-15**（ユーザー提供の観戦スクショ・3倍拡大）: 「黒コミ3又3/4子」「0子 アゲハマ 0子」を正しく
  読めた。対応表は「3又3/4子→中国 7.5」「6目半→日本 6.5」「7目半→7.5」など。読めない・表に無い場合は
  入力欄を開く。呼ぶのは開始時と `reimport` 時だけ（毎周は呼ばない）
- アゲハマの左右は**その側の対局者が取った数**（左＝白の対局者欄＝白が取った数、右＝黒が取った数）。
  **実測 2026-11-15**（2枚目のスクショ・98手目・表示「0子 アゲハマ 3子」）: 既存の認識で盤上は黒49・白46。
  98手なら黒白49手ずつ＝白石が3つ取られている＝黒のアゲハマ3＝右の数。1枚目（85手目・0／0）も
  黒43・白42で一致。両スクショとも文字認識は「0子 アゲハマ N子」の行を正しく読んだ
- ルールは窓タイトルに「中国ルール」等があればそれを優先し（2枚目のタイトル
  「…観戦中 [98手目] - レーティング - 中国ルール」・Win32 で読める）、無ければ（1枚目「… - 大会」）コミの表記から決める
- 盤の認識は観戦画面でも既存のままで通る（上の2枚で石数・直前手の色とも整合。手数字つきの石「6」と
  空点の黒い四角も誤認しない）。2枚はテストデータ `tests/data/board_watch_fox_spectate{1,2}.png` にする

### 5.5 汎用化の準備

- 盤種ごとの差（窓タイトル・盤の検出・直前手の印・対局情報の読み取り）を `BoardProfile` として
  登録する表を作り、いまの3種（黄盤・木目盤・野狐）を載せる。検出の順序と結果は変えない
- `python -m katrain.core.board_watch --save-sample [窓タイトル]`: 窓のスクショを
  `~/.katrain/board_samples/` へ保存する。新しい盤に対応するときの材料集め用

### 5.6 対象の画面

プロの対局（大会対局室）も通常の対局室と同じ作りで読める。1枚目のスクショは大会の中継
（窓タイトル「> [高級対局室1] > 46453号大会対局室　観戦中 [85手目] - 大会」）で、「対局室」と `[N手目]` を
含み、対局者パネル・アゲハマの行も同じ位置。右の「変化図」はリンクで、盤上には描かれていない。
パネルの位置は盤矩形の右隣として相対で決める（右端のサイドバーは入れない＝入れると 1 枚目でコミの行が
消えた）。文字認識はコミの表記そのもの（「3又3/4子」など）と「アゲハマ」で拾い、見出しの「黒コミ」には頼らない
（1 枚目で「コ」を読み違えた）。
コミの表記が対応表に無いときは推測せず入力欄を開く。

## 6. 制約・既知の限界

- 自動反映 OFF の間の手順は静止画から復元できない（5.1 の推定か取り込み直し）
- 途中から取り込んだ局面より前の手は分析できない
- コウの取り返しなど「石数が変わらない2手」は `reimport` になる

## 7. テスト

- `spectate_sync` の単体テスト: 1手／取りを含む1手／複数手（推定）／石が消える／手数不一致／サイズ違い
- 既存の `tests/test_board_watch*.py` が無変更で通ること（対局・詰碁監視の非回帰）
- 野狐の観戦スクショ（ユーザー提供）で 盤の認識・`[N手目]` の解析・対局情報の読み取り
- 実機: 野狐の観戦で 開始→自動反映→OFF→数手後に `今すぐ反映`→過去手の検討中に着手が来る、を通す

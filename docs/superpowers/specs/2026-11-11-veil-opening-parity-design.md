# 一致率ひかえめ：序盤の互角外し（`<prefix>_parity_*`・既定 OFF）設計

2026-11-11。対象は `ai:veil9` / `ai:veil13` / `ai:veil19`（`Veil9Strategy`）。親 spec は `2026-09-23-veil-strategy-design.md`。

**状態（2026-11-12）: 📝 設計のみ・未実装**。13路の自己対局（§2）の結果、ユーザーの決定で既存のスライダー 2 つ（同値外しの
`free_wr_drop` 5%・`free_loss` 0.5）をユーザーの設定に入れていったん終了（§7。13路で測り、9/19路も同じ値に）。§3 の互角外しの層はコードに存在しない。

## 0. 一言で

相手が強い（高段者 BOT）と、序盤のこちらの最善手一致率だけが相手より高くなる。その原因は、互角の局面で外しを許す
「同値外し」の関門が狭いこと（1手の勝率低下 3% ≒ 13路で 0.15 目）。そこで**序盤の窓の中だけ**、
**一致させるとこちらの一致数が相手を上回る手番に限り**、関門を広げる（1手 0.5 目・勝率低下 6% まで）。
広げたぶんの損は1局の予算で頭打ちにする。窓の後の挙動は今と同じにする。

## 1. 要件（ユーザー・2026-11-11）

1. 相手が高段者のとき、序盤（30〜40手）のこちらの一致率を「相手と互角か少しだけ低い」に保つ。
   勝率 50% 付近を保ち、少しの劣勢は許す。
2. 相手が序盤に損をして自滅しているなら、この限りではない（リードが増えれば既存の支払う外しが働く）。
3. 序盤は着手の表示まで少し時間がかかってもよい。
4. 相手のミスで生まれた余裕を、既存の損をする外しに回し、全体の一致率もさらに下げる。

**親 spec の要件3（「相手より低い」は目標にしない）を、序盤の窓の中に限って上書きする**（ユーザーの新しい決定）。
窓の外は絶対目標（`target_rate`）のまま。

**勝ちの基準（ユーザー・2026-11-11）**: 持碁は負けに数える。強い相手（序盤の一致率 55〜65% の BOT）に 20 局で
持碁・負けが 5〜6 局まで（勝ち 14〜15 局以上）なら許す（もっと負けてもよいかもしれない）。その強さの相手に 20 局中 2 局しか
負けないのは、それ自体が人間の強さを超えている。**相手がまったく間違えない（罠にかからない）なら、無理に勝つ必要はない**。
→ 親 spec の要件1（勝ち最優先）を、強い相手に対しては「勝ち 70〜75%」まで緩める。検証の相手は「強いが時々間違える」BOT にする
（§2.6）。0.5 目以上の損を打てない相手 O2（§2.3）での結果は、相手がほぼ間違えない最悪の条件として扱う。

## 2. 実測（設計の根拠）

### 2.1 実戦ログ（33局・2026-09-26〜11-06。読み取りだけ）

- 13路で「強い相手 × こちらの序盤一致率が高い」局は、すべて研究外し ON（`veil13_open_moves=30`）で打っていた。
  今の設定（研究外し OFF）では、強い相手との 13路の対局ログは無い。
- 2026-09-27 の 13路（黒・相手の序盤一致率 67%）: 自分の一致率は 30 手目まで相手以下（10/15 対 11/15）。
  任せた先（難解＋と 9段委譲）の外し5回でリードを −1.6 目失い、そのあと**劣勢ロック**に入った
  （lead < −1 で同値外しの上限が 0.1 目＝`VEIL_BEHIND_LIMIT`。lead < reserve なので支払う外しも閉じる）。
  結果は終局まで 77% 対 69%・負け。
- 「こちらの一致率 65% 以上」は強い相手の目印にならない（6局中3局は相手が弱い局）。**目印は相手自身の一致率**で、
  判断の時点で `Rate:` 行に出ている（`opp` / `n_opp` / `opp_trunc`）。

### 2.2 互角の序盤で外しを止めているもの（コード）

- 支払う外し: S = lead − reserve > 0 が要る＝互角では閉じる。forced 層は root 勝率 >= 0.70 と lead > forced_min_lead が要る＝閉じる。
- 同値外し: cost <= free_loss（13路 0.4）**かつ** 最善手との勝率差 <= free_wr_drop（3%）。13路の互角付近の勾配は
  約 20pp/目なので、実効の上限は約 0.15 目。候補の足切り `raw_cap = F_eff + 0.3`。
- 劣勢（lead < −1）では F_eff が 0.1 に下がる。

  局全体への効果は約 −3pt にとどまる見込み（窓の中 −11pt × 窓の手番の割合）。
- 序盤の同値外しのうち「一致させても相手を上回らない手番」で打たれたもの: cur 3.45 回/局（0.26 目）・wfree 6.0 回/局（0.70 目）。
  **相手基準の関門で削れる上限は、その差 +2.5 回/局・+0.44 目**（つり合った後の効果はこれより小さい）。

## 3. 設計

> **注（2026-11-12）**: §2.7 のとおり、残りの差の大半は「自然な代替手が無い手番」で、本層はそれを解決しない。本層の利点は
> O7 型（ほとんど間違えない）の相手で、窓の中の損を必要な手番に絞って窓の後の支払う外しの余剰を残すこと＝**測っていない見込み**。

### 3.1 流れ（S6〜S9 の F_eff と free_wr_drop の決め方だけを変える）

既存の流れ（候補のプール → 自然さの床 → プローブ → `veil_choose`）はそのまま使う。変えるのは、窓の中で
「互角外しが要る」手番の同値外しの関門だけ。

1. **窓**: `index = veil_open_index(depth, n_setup) < parity_moves`。ヨセは対象外。`open_moves` の窓の手番は
   研究外しが先に返る（S4b）ので、互角外しは動かない（両方 ON のときは研究外しが勝つ）。
2. **要否（クエリ 0 本）**: `need = mine + 1 > opp_trunc`（この手も一致させると、同じ手数で見たこちらの一致数が相手を上回る）
   かつ u > 0。白番は `opp_trunc` が自分の手数にそろえた相手の一致数（既存）。
3. **予算と床**: 今局の互角外しで追加に払った損の合計 `spent < parity_budget`、かつ lead >= `parity_min_lead`。
4. 1〜3 を満たす手番だけ、`F_eff = parity_max_loss`、`free_wr_drop_eff = parity_wr_drop` とする
   （劣勢ロック `VEIL_BEHIND_LIMIT` は、窓の中では `parity_min_lead` に置き換える）。`raw_cap` も `F_eff + 0.3` で連動して広がる。
5. 選んだ手の cost が通常の関門（free_loss・free_wr_drop・劣勢ロック）を超えていれば、その手は**互角外し**として扱う。
   - 打つ前に、最善手と選んだ手を `parity_verify_visits`（既定 1500）で読み直し、cost <= parity_max_loss・
     lead − cost >= parity_min_lead・勝率差 <= parity_wr_drop を確かめる。満たさなければ通常の関門で選び直す
     （500 visits の勝率差 1 組はノイズが大きい＝実測で生 0.2 目が検証で 0.5〜1.1 目に化けた）。
   - `spent += max(0, cost − free_loss)` を `game._veil_state[prefix]["parity"]` に足す（打ったときだけ作る）。
6. Decision の kind は `parity`（tier iii）。フィールド `parity`（gate / no_need / budget / floor / rejected / played）・
   `parity_gtp` `parity_cost` `parity_wr_drop` `parity_spent`。

### 3.2 設定（5 キー × 3 盤・既定 OFF）

| キー | 意味 | 候補値 | 既定 9 / 13 / 19 |
|---|---|---|---|
| `parity_moves` | 互角外しの窓（打つ手の番号がこの値以下）。最大値は「局全体」＝相手基準の関門だけで止める | OFF／9路 6〜30・13路 10〜60・19路 20〜100／局全体 | OFF |
| `parity_max_loss` | 互角外し1手の損失の上限（目） | 0.2〜1.0 | 0.4 / 0.5 / 0.6 |
| `parity_wr_drop` | 互角外し1手で許す勝率低下 | 2%〜10% | 6% / 6% / 6% |
| `parity_budget` | 互角外しで追加に払う損の1局の上限（目・通常の同値外しを超えた分） | 0.2〜3.0 | 0.6 / 1.0 / 1.5 |
| `parity_min_lead` | 互角外しの後に残すリード（目） | −3〜+1 | −1 / −1 / −2 |

値は仮置き。§4 で決める。

## 6. 却下・保留した案

- 研究外し（`open_moves`）の窓を長く・短くする: 強い相手には窓の中で一致率が下がらず、リードを失う（§2.3）。
- 安全条件のスライダーをゆるめる（reserve 1・min_winrate 0.6）: 勝ちが 7/20 に落ちる（§2.3 loose）。
- 劣勢ロック（`VEIL_BEHIND_LIMIT`）を全局で外す: 窓の後の接戦で累計の損が増える見込み（wfree の窓の後の結果からの推測で、測ってはいない）。
- 研究外しの 9段委譲を短くする（11 → 4）: 良くならない（§2.4）。
- プローブの本数を増やす: 自然な候補 78 手のうち 77 手は既にプローブされていた（実戦ログ）。在庫は関門の外にある。

## 7. 結論とユーザーの決定（2026-11-12）

- **研究外し（`open_moves`）は強い相手には使わない**: O2・O7・O3 のどれでも自分の一致率は下がらない（序盤 −5〜+7pt・局全体 −4〜+8pt。
  9段委譲を 11 → 4 にしても良くならない）。相手の一致率を下げるので差はむしろ開く。ほぼ間違えない相手（O2）には 40 手目のリードを
  2.2〜2.8 目失い、勝ちが 9/20 に落ちる。ユーザーの 13路の設定は 2026-10-11 から既に OFF。
- **同値外しを広げる（free_wr_drop 3% → 5%・free_loss 0.4 → 0.5。どちらもスライダーの上限）**を、ユーザーの 13路の設定
  （`~/.katrain/config.json` の `ai:veil13`）に入れた。コードの既定値は変えていない。同日、ユーザーの決定で 9路・19路（`ai:veil9` / `ai:veil19`）も
  同じ値にした（9/19路の効果と勝ちへの影響は測っていない）。
  - ミスもする強い相手には勝ちを落とさない（O7・O3 で 40-0）。ほぼ間違えない相手（O2）には勝ちが減る（25/40 対 cur 47/60・p 0.11）が、
    ユーザーはこれを許す（§1）。
  - 自分の一致率: 序盤 40 手は O2 −11〜−17pt・O7 −7.3pt・O3 −2.4pt（差は見えない）、局全体は O2 −8.6〜−9.4pt・O7 +0.4pt（差は見えない）・
    O3 −5.6pt。相手の一致率との差は O2 で逆転（自分が下）、O7 は序盤で逆転・局全体でほぼ並ぶ、O3 は約 6pt 上のまま。
- **目標の「相手並み（44〜48%）」には届かない**。律速は予算ではなく在庫（§2.7: 投了時にリードが O3 で +11 目・O7 で +4 目残り、
  窓の後の最善手の手番の 6〜8 割は 9段らしさの床の上に上限内の代替手が無い）。互角外しの層（§3）はこれを解決しないので実装しない。
  さらに下げるには 9段がめったに打たない手（hp 5% 未満）も外す先に使う必要があり、人間らしさとの交換になる（ユーザーは今回は見送り）。

  `calibration-data/selfplay/veil_arm_report.py <dir...> --w 40 [--base cur]`（腕ごとの窓 W の一致率・リード・kind/why・対の差）と
  `veil_win_stats.py`（相手選び用の窓の要約）。

# 詰碁画面キャプチャ→KaTrain自動反映 設計書

日付: 2026-07-28
ステータス: 設計承認済み

## 目的

PC上で動作する詰碁アプリ（BlueStacks App Player 上の Android 詰碁アプリ、13路盤・常に黒番）の盤面を、グローバルホットキー一発でキャプチャ・認識し、KaTrain の盤面に石を配置して詰碁外枠（F10 相当）まで自動適用する。ホットキー押下から盤面+外枠完成まで 1〜2 秒、KataGo 解析開始まで含めて 3〜4 秒を目標とする（要件: 5〜10 秒以内）。

## 前提・確定事項

- 対象アプリは固定: BlueStacks App Player（ウィンドウタイトル部分一致 "BlueStacks"）上の詰碁アプリ
- 盤は常に 13 路、手番は常に黒（`PL[B]`）
- サンプル画像 `tests/data/tsumego_app_sample.png`（`c:\temp\詰碁アプリ画像.png` 由来）で確認した描画特性:
  - 盤は鮮やかな黄色の矩形で、背景（青系）と明確に分離できる
  - 格子は規則配置: セル幅 = 盤幅/13、第1線は盤端から半セル内側
  - 石は白・黒ともコントラストが高い。星（小さな点）は交点パッチの平均色に埋もれる
  - 「黒番」表示・問題番号は盤矩形の外にあり干渉しない

## 全体構成

新規モジュール + 既存 GUI への少量のグルーコード。

```
Ctrl+Shift+G（グローバルホットキー、keyboard ライブラリ）
  → BlueStacks ウィンドウ検出（ctypes/Win32 API、タイトル部分一致）
  → ウィンドウ矩形をスクリーンキャプチャ（PIL ImageGrab）
  → 盤面認識 → SGF 文字列生成（SZ[13] AB[...] AW[...] PL[B] KM[新規対局既定値]）
  → KaTrain メッセージキューへ（tsumego-capture-apply 単一メッセージ）
  → _do_new_game(move_tree=parse(sgf)) → _do_tsumego_frame(ko=False, margin=4)（同一ハンドラ内で同期実行）
  → KaTrain ウィンドウを前面化
```

### コンポーネント

| コンポーネント | 場所 | 責務 |
|---|---|---|
| 認識モジュール | `katrain/core/tsumego_capture.py`（新規） | ウィンドウ検出・キャプチャ・盤検出・石分類・SGF 生成。**Kivy 非依存**で単体テスト可能 |
| GUI グルー | `katrain/__main__.py`（追記） | 起動時のホットキー登録、コールバックでの認識実行、メインスレッドでの盤面反映+外枠適用+前面化、エラーのステータス表示 |
| 設定 | `katrain/config.json` + ローカル `C:\Users\iwaki\.katrain\config.json` | `tsumego_capture` セクション（下記） |
| テスト | `tests/test_tsumego_capture.py`（新規） | サンプル画像での認識結果検証 |

## 盤面認識ロジック

1. **盤検出**: 黄色ピクセルのマスク（R 高・G 高・B 低の閾値、サンプル画像でキャリブレーション）を作り、最大の黄色連結領域のバウンディングボックスを取得。BlueStacks のアイコン等の小さい黄色領域は面積で除外。検証: 矩形がほぼ正方形（アスペクト比 0.9〜1.1）かつ短辺 300px 以上
2. **格子推定**: セル幅 = 盤幅/13、交点 (i, j) の中心 = 盤左上 + セル幅 × (index + 0.5)。個別の線検出は行わない
3. **石分類**: 各交点中心の小パッチ（セル幅の約 25%）の平均色で 3 値判定
   - 暗（低輝度）→ 黒石
   - 明るく低彩度 → 白石
   - 黄色系 → 空点
   - どれとも言えない → 曖昧セルとしてエラー（読み取り中止）

閾値はサンプル画像から決め、ユニットテストで固定する。

## SGF 生成と KaTrain 反映

- SGF: `(;GM[1]FF[4]SZ[13]KM[<既定komi>]PL[B]AB[..]..AW[..]..)` 形式の文字列を生成。komi は KaTrain の新規対局既定値を使用
- 反映: 既存の `KaTrainSGF` パーサで parse し `_do_new_game(move_tree=...)`。続けて `_do_tsumego_frame(ko=False, margin=4)`（`__main__.py:530`、F10 ポップアップの既定値と同じ margin=4）。`PL[B]` により `next_player_info.player == "B"` となり黒番として外枠が生成される
- 反映後、Kivy Window を前面化（restore + raise）してすぐ検討に入れる状態にする

## 設定

`config.json` に新セクション（パッケージ側・ローカル側の両方に追加。ローカル側はメインセッションで直接編集する）:

```json
"tsumego_capture": {
  "enabled": true,
  "hotkey": "ctrl+shift+g",
  "window_title": "BlueStacks",
  "board_size": 13,
  "frame_margin": 4,
  "frame_ko": false
}
```

- GUI 設定画面への追加はしない（設定ファイル直編集のみ）
- `enabled: false` でホットキー登録自体をスキップ
- 依存パッケージ `keyboard` を `pyproject.toml` に追加（Pillow / numpy は既存依存を利用）

## エラー処理

すべての失敗は KaTrain のステータスバー表示 + ログ出力で通知し、クラッシュさせない:

| 状況 | 挙動 |
|---|---|
| BlueStacks ウィンドウが見つからない | 「ウィンドウが見つかりません」表示 |
| 黄色い盤が検出できない（最小化・遮蔽等） | 「盤面を検出できません」表示 |
| 曖昧な交点が 1 つでもある | 読み取り中止しエラー表示（誤配置で解くより安全） |
| keyboard ライブラリ初期化失敗 | ログ警告のみ、KaTrain 本体は通常起動 |

認識はホットキーのリスナースレッドで実行し（〜数百 ms）、反映は message queue（`tsumego-capture-apply`）経由でメッセージループスレッドで実行し、ウィンドウ前面化のみ `Clock.schedule_once` で行う。

## テスト

- **ユニットテスト** `tests/test_tsumego_capture.py`: サンプル画像に対し、盤検出矩形の妥当性と全 169 交点の分類結果（サンプル画像の実配置。正確な座標リストは実装時に目視で確定しテストに固定）を検証。ホットキー・ウィンドウ検出・GUI 反映はテスト対象外（Windows 実環境依存のため）
- **オフライン CLI**: `python -m katrain.core.tsumego_capture --image <path>` で ASCII 盤面と SGF を表示（KaTrain 起動不要でキャリブレーション確認）。Kivy を import しないモジュールだが、慣例に従い argparse 使用時は先頭で `KIVY_NO_ARGS` を設定
- **E2E 手動確認**: BlueStacks + KaTrain 実環境でホットキー→外枠適用→解析開始までを確認

## 採用しなかった案

- **外部常駐スクリプト + クリップボード + キー送出**: F10 がポップアップを開くため外枠自動適用のキー送出が脆弱。ウィンドウアクティブ化のタイミング問題もあり不採用
- **外部スクリプト + ローカルソケット受信**: プロセスが 2 つ + 通信層が増え、KaTrain 内蔵に対する実利がないため不採用
- **PrintWindow による背面ウィンドウキャプチャ**: ホットキーを押す時点でユーザーは BlueStacks を見ている（前面にある）ため不要（YAGNI）

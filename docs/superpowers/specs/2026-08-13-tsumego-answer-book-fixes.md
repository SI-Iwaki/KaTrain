## 2. コウ絡みの「問題側の正解定義」と解析側の齟齬（分析）

### 2.1 アプリのコウの扱いは現行のクラス順序と整合している

ソルバ経路の per-decision で df-pn が `class=KO` と裁定した手番は **KO 一致 171 / KO 不一致 15**。
一致 171 件は全部 `komaster=B`（攻め方をコウマスターとみなす）＝**アプリは「コウで殺す/生きる」を
正解として受け入れており、コウダテ前提（ko_win_assumption）の設計と整合**。

### 2.2 齟齬その1: df-pn が KO と言うのにアプリの正解手順にコウが無い（抽出の別問題疑い）

旧スイープの KO 裁定不一致 17 件のうち **15 件は、アプリの記録手順にコウの応酬が一切現れない**
（盤リプレイでコウ取り返しを検出）。しかも多くで記録手が KataGo の visits 1位・損失最小
（例: c243c4dbaa 記録手 E5 pt+0.12 v1336 vs ソルバ手 C6 pt+13.99 v30）。
**df-pn の「無条件では解けない＝コウが最善」という証明が、画面の詰碁ではなく抽出した別問題に
対するもの**という構図。target が広すぎる（アプリの成功条件は要石の殺し/生きだけなのに、
抽出が捨ててよい石まで target に含める）等が原因候補。

現行の安全網 `solver_cross_check` がこれを部分的に捕まえる（旧 true_miss 13 → 7 件回復）が、
**答えがコウ/セキ級の局面では ply1 ownership が成否を運ばず、両者「不成立」で却下できない**
（実測 8/13: 継続誤答のソルバ経路 29 件中 12 件が「本命も成立していないためソルバの答えを残します」）。
これは case I/Q と同じ**エンジン側の限界枠**（ply1 で成否が出ない以上、ownership 軸では原理的に
裁定できない）。

**目数乖離ゲートは実測で却下**: 「ソルバ手の pointsLost − KataGo 最善候補の pointsLost > T なら
却下」は、**KO 一致（正解）側にも gap +2.0 超が 12 件**あり（KataGo がコウの正解手を過小評価する＝
ソルバモードの存在理由そのもの。最大 +6.92）、mismatch 側（+0.0〜+13.87）とレンジが重なる。
T=4 で「捕まえ4 / 壊し4」＝シャッフル。

### 2.3 齟齬その2: 守り方でコウを持ち上げた実例（→ 修正 B）

b5553318（frame・守り方・d8）: 通常最善 B2 の root lead が **−5.78 目**（枠の代償地帯が未決着で
スコアが詰碁から切り離れていた）ため「既に成功」スキップが効かず、コウ勝ち前提 +23.96 目の A1 を
採用して誤答。**B2 の子局面は役割石 +0.99/子＝無条件で生きていた**。守り方の順序
（無条件生き > セキ > コウ）に対し、スコア比較だけでコウを採ったのが齟齬。

## 3. 実装した修正（4件）

すべて `katrain/core/ai.py`。共通原則: **解析条件は変えない**（手の入れ替えシャッフルを構造的に
避ける）。増えるのは「既に測った値の利用」と「発火が確定した手番だけの追加クエリ」のみ。

### A. cross-check の実測値をフォールバック先へ引き継ぐ（`_cross_check_measured`）

却下時に測定済みの {手: 役割石/子} を保持し、フォールバックの ai:tsumego が
**「積極的に失敗」と実測済みの手を選び直したら、成立を実測済みの本命へ差し替える**。
実測 e6794025: C2 却下（−0.60/子）→ ai:tsumego が C2 を再選択（救済の全リージョン石スケールでは
E2 との差 +0.48 < margin 1.0 で正解 E2 を却下していた）→ 差し替えで E2。

**発火条件の締め（フルスイープ A/B で1回転した）**: 初版は「選択手 < 閾値(0.5)」で発火させて
いたが、A/B で**未決着帯の正解手を2件壊した**（125cac90 の E1＝コウ経路 −0.05/子 ／
210cce8e の D1 +0.20/子。どちらもアプリの正解＝閾値近傍は答えがコウ等で ply1 ownership が
成否を運ばない局面）。回復側 e6794025 の C2 は **−0.60/子＝積極的失敗**（役割石を相手に
取られている）で両帯は分離できるため、条件を「選択手 ≤ **−閾値**」に締めた。
締めた後の標的3ケース×3run（別プロセス）は **9/9 correct**（e6794025 は発火して回復を維持、
壊れた2件は不発火で correct に復帰）。

### B. コウ勝ち採用の直前に「通常最善の子局面検証」を課す（`_pick_ko_win_move`）

採用が確定した手番だけ、通常最善手の子局面を同深さ（gain_verify_visits・wRN=0）で検証し、
役割石 1子平均 >= ko_success_ownership なら**コウを採用しない**（root スコアは枠の代償地帯で
汚れうるが、子局面の役割石はその影響を受けない）。役割が読めない盤では走らない。
校正済みのコウ採用は通常最善が本当に失敗している＝子局面でも成立せず挙動不変（E2E で回帰確認）。

### C. クラス格上げの候補に visits 上位を和集合で足す（`_ko_promotion_choice`）

prior 上位 `ko_escape_candidates` 本だけだと「root が実際に読んだ（v282=visits2位）のに
prior 6位」の正解手を測り落とす（実測 15fafed5）。visits>=10 かつ prior>=min_prior の
visits 上位を和集合で追加。case O（正解が v1＝priorしか信号が無い）の探索先は不変。
採否は従来どおり1手ずつの成立検証なので、増えるのは probe の本数だけ。

### D. 同深さ検証の覆しに役割石の両側ゲート（`_verified_choice` + `role_context`）

**incumbent が役割石で成立していて挑戦者が成立していない**ときだけ覆しをブロックする。
実測 62a94083: 正解 A7（+0.99/子）を、全リージョン石合計スケールで +5.33 上回る B4（−0.56/子）が
救済で置き換えて誤答／fad4fe69 も同型。
spec 追記36 で却下済みの「挑戦者の成立要求」ゲート（片側）とは方向が逆で、
**新しい覆しを許可することは決してない**（ブロック専用）。校正済みの正しい覆し（G2/H/F2）は
incumbent 側が失敗している（だから覆しが要る）ので素通りする。

### 直せなかった残余（既知の限界として記録）

- 閾値近傍の単発読みの run 間分散（±0.95 の二峰性）による flip: 402f938db1（cross-check の
  stage2 が正解 C5 を「不成立」と読んだ run）・2b74613ed4（格上げ probe が +0.28/子）・
  86363318b4（stage1 が +0.45〜0.5 近傍）・4d3f678f77（root movesOwnership +0.37 近傍）。
  読みを増やす/深くする系は 2026-08-10 spec 6.1 で差引マイナスが実証済みのため追わない
- ソルバ経路の KO/SEKI 級で「本命も不成立」の 12 件（2.2 節の限界枠）

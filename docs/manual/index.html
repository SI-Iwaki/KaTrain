KaTrain v1.17.1.1 修正版 — User Manual

KaTrain 改修版
完全マニュアル

囲碁 AI「KataGo」で対局・分析・勉強ができるアプリ KaTrain の、改修版（Human-like AI 戦略・詰碁・盤面監視つき）の使い方を、 初めての方でも上から順に読めば分かるようにまとめました。AI の設定項目は「値を上げると／下げるとどうなるか」まで書いてあります。

01はじめに

KaTrain とは

KaTrain は、囲碁 AI KataGo を使って「AI と対局する」「棋譜を分析して悪手を教えてもらう」ことができるデスクトップアプリです。 元のソフトは sanderland/katrain（オープンソース）で、 このマニュアルが扱うのはそれに次の 3 系統の改修を加えた v1.17.1.1 修正版です。

① 人間らしい AI 戦略の追加「9段の人間ならこう打つ」という humanSL モデルを土台に、力戦派・攻城・狩猟・持碁・一致率追随・難解など、目的別の棋風を選べる AI を多数追加。設定はスライダーで細かく調整できます（→ 06 AI 戦略ガイド）。
② 詰碁の自動解答BlueStacks 上の詰碁アプリや Web の詰碁をホットキー一発で読み取り、KaTrain 上に再現して AI が正解手を打ちます。死活ソルバ・回答帳・自動ループつき（→ 07 詰碁機能）。
③ 対局アプリの盤面監視BlueStacks 上の対局アプリの相手の着手を自動で KaTrain に取り込み、AI の応手をアプリの盤の上に光る輪で示します（→ 08 盤面監視モード）。

このマニュアルの読み方

  • 初めての方は 02 インストール → 03 画面の見方 → 04 対局する の順に読んでください。30 分で一局打てるようになります。
  • AI の棋風を変えたい方は 06 AI 戦略ガイド へ。冒頭の「戦略の選び方」早見表から目的の戦略に飛べます。各設定項目には 上げると / 下げると どうなるかを書いてあります。
  • 本文中の F7 のような表記はキーボードのキー、「一般・エンジン設定」のような「」つきの語は画面に表示されるボタンやメニューの名前です。
  • 専門用語（humanPolicy・ownership・visits・目 など）は 付録の用語集 にまとめました。
スクリーンショットについて 本書の画面写真は、この改修版 KaTrain を実際に起動して自動撮影したものです（言語設定は日本語、ウィンドウサイズ 1500×1000）。 お使いの環境ではウィンドウサイズやテーマによって配置が多少変わりますが、ボタンやメニューの名前は同じです。

インストール手順

  1. リポジトリのフォルダ（例 C:\Users\<あなた>\Documents\katrain-1.17.1.1\katrain-1.17.1.1）でコマンドプロンプトを開きます。
  2. uv sync を実行して依存パッケージ（Kivy・KivyMD・Pillow など）をインストールします。uv が無い場合は pip install -e . でも構いません。
  3. python -m katrain で起動します。初回は KataGo が GPU 向けにチューニングするため、起動に 1〜2 分かかることがあります（右下のランプが緑になれば準備完了）。
  4. 起動後に F8（一般・エンジン設定）を開き、KataGo・モデル・humanSL モデルのパスを確認します（下記）。
cd C:\Users\<あなた>\Documents\katrain-1.17.1.1\katrain-1.17.1.1
uv sync
python -m katrain

対局モードと分析モード

右パネルの「対局」「分析」ボタン（または Tab）で切り替えます。それぞれのモードで「どのチェックボックスを ON にしていたか」「右パネルのどのタブを開いていたか」が別々に記憶されるので、 「対局中はヒントを出さない／分析中はすべて表示」のように使い分けられます。

ドットの色の意味

着手の上に付く色つきの点は「その手で何目損したか」を表します。既定のしきい値（指導・分析設定で変更可）は次のとおりです。

色損失（目）読み方
緑0.5 未満ほぼ最善。
黄緑0.5〜1.5小さな緩手。
黄1.5〜3やや損。
オレンジ3〜6はっきりした悪手。指導対局ではここから「待った」がかかります。
赤6〜12大きな悪手。
紫12 以上致命的。

点の大きさは「その損が実際に相手に咎められたか」を表します（最大＝丸ごと咎められた、最小＝結果的に目差は動かなかった）。級位者は赤・紫の大きい点だけ見れば十分で、有段者は小さな点も参考になります。

最小表示（集中モード）

F12（または `）を押すたびに、右パネル → 上部トグルの順に非表示になり、碁盤だけの表示になります。もう一度押すと戻ります。

新規対局を始める

メニュー →「新規対局・ルール変更」（Ctrl+N）で次のダイアログが開きます。

項目説明
対局者名棋譜（SGF）に記録される名前。空欄でも構いません。
プレイヤー（黒／白）「人間」か「AI」。人間のときは「通常対局」「指導対局」を、AI のときはAI の戦略を選びます。丸いアイコンで黒白を入れ替えられます。

局面を生成（自己対局で途中局面を作る）

対局情報を編集

対局者設定（人間 / AI・戦略の切り替え）

対局の途中でも、メイン画面の右パネル上部（またはメニュー →「対局者設定」）で黒白それぞれの「人間 / AI」と AI の戦略を切り替えられます。 戦略の細かい設定は F7「AI設定」で行います（→ 06）。

指導対局（悪手を自動で待った）

人間側を「指導対局」にすると、KaTrain があなたの手を毎回分析し、しきい値より損な手には自動で「待った」をかけて打ち直させます。 待ったの回数・しきい値は「指導・分析設定」（F6）で決めます。

項目意味
何目より損ならドットの色分けのしきい値（既定 12 / 6 / 3 / 1.5 / 0.5 / 0 目）。
再考を促す回数指導対局でその色の手に何回まで「待った」をかけるか。既定は紫・赤・オレンジが 1 回、黄が 0.5（確率 50%）、それ以下は 0。
カラーテーマドットの配色。「赤緑色弱」向けのテーマがあります。
候補手上の表示上位候補に表示する数字の種類（損失目数／目差／勝率／探索手数など）。2 つ目は副表示。
表示候補の最低探索数これより探索手数が少ない候補は数字を出しません（小さく薄い点になる）。
直近何手のドットを表示「ドット表示」が「直近だけ」のとき、何手ぶんまで点を付けるか。
AIの手にもドット／コメントをつけるOFF にすると人間の手だけに点やコメントが付きます。
分析結果をSGFに保存ON にすると保存する棋譜に解析結果を埋め込み、次に開いたとき解析なしで表示できます（ファイルは大きくなります）。

05分析する

棋譜を読み込む・保存する

  • 読込: メニュー →「棋譜読込」（Ctrl+L）。SGF のほか NGF・GIB も読めます。ファイルをウィンドウにドラッグ＆ドロップしても開けます。
  • クリップボードから: SGF のテキストをコピーして Ctrl+V。全手を簡易解析し、最終手だけ通常解析します。
  • 保存: 「棋譜保存」（Ctrl+S）／「名前をつけて棋譜保存」（Ctrl+D）／Ctrl+C でクリップボードへ。既定の保存先は一般設定の sgf_save（このリポジトリでは sgfout/）。

キーチェックボックス表示されるもの
q次の着手棋譜で次に打たれた手（分岐がある場合はすべて）。次の一手を当てる練習のときは OFF に。

分析オプション（深い分析のメニュー）

「分析オプション」ボタンを押すと次のメニューが開きます。各項目はキー 1 つでも呼び出せます。

キー項目何をするか
aさらに深く分析今の局面をより多くの探索手数で読み直し、評価の精度を上げます。
s候補手を均等に分析表示中の候補手をすべて最善手と同じ探索手数まで読ませ、薄い点の候補の信頼度を上げます。
d盤上すべての手を簡易分析打てる手を全部軽く評価します。「まともな手が何通りあるか」を見るのに便利。

AI 設定画面の使い方

メニュー →「AI設定」（F7）で開きます。

  • 説明欄: 戦略の概要のあとに【各項目】として、画面の上から順に「■ 英語のキー名（日本語名）［既定 値］: 解説」が並びます。画面の項目名は英語のキー名なので、説明欄の同じキー名を探せばどのスライダーの解説か分かります。説明欄をクリックすると大きな画面で開き、大きめの文字でスクロールして読めます（「閉じる」か Esc で戻る）。
  • 項目欄: 項目が多い戦略（力戦派・難解＋・持碁など 20 項目前後）は項目欄がスクロールします。右端のスクロールバーかマウスホイールで動かしてください（スクロールする戦略では、項目欄の上のホイールはスライダーではなくリストを動かします）。
  • 推定段級位: 校正済みの戦略（段級位相応・損も混ぜて・第一感系）では、設定値から強さの目安が表示されます。humanSL 系は「?」のままです。
  • スライダー＋数値ボックス: スライダーは決められた候補値に吸い付きます。候補にない値は右の数値ボックスに直接入力すれば保存できますが、その後スライダーを一度でも動かすと最寄りの候補値に戻ります。
  • 色の薄いスライダー（上のほうの項目）は「校正済み・強さに直結する」項目、濃いものは補助的な項目です。
  • チェックボックスは ON/OFF の機能スイッチ。
  • 設定は戦略ごとに別々に保存されます（例: 「難解（9路）」と「難解（13路）」は別の値）。
  • 設定画面の項目名は英語のキー名のまま表示されます（例 hunt_max_loss）。説明欄の【各項目】と本章の表はそのキー名で引けるようにしてあります。
  • 本章のスクリーンショットに写っている数値は撮影した環境の現在値で、必ずしも既定値ではありません。既定値は各表の「既定」列を見てください。

共通の考え方: 「損失」「humanPolicy」「安全弁」

改修版の戦略の設定項目を読むには、次の 3 つの言葉を押さえておくと楽です。

言葉意味設定でよく出る形
損失（目）KataGo の最善手と比べて「その手を打つと何目損するか」。0 が最善手。人間らしい戦略は、候補の中から損失がしきい値以下の手だけを残してから選びます。*_max_loss「損失上限」。上げる＝より損な手も打つ＝弱く・個性的に、下げる＝最善手に近づく＝強く・AI っぽく
humanPolicyhumanSL モデルが出す「その段位の人間がその手を打つ確率」。高いほど自然な手。多くの戦略は候補をこの確率で重み付けして抽選します。min_human_policy「humanPolicy 下限」。下げると「人間があまり打たない手」まで候補に入る
安全弁どの戦略にも入っている保険。重み付けで選ばれそうな手が 4 目以上損なら KataGo の最善手に差し替えます（攻撃型）／勝率が下限を割る手は打たない（一致率追随・難解）。設定をどう変えても大崩れしないのはこのためです。*_min_winrate「勝率フロア」など
序盤・中盤・ヨセ 多くの戦略は「序盤は厳しく、中盤は緩く、ヨセ（終盤）は最善手に戻す」という 3 段構えです。序盤の境界は盤の交点数の 14%（19路 51 手・13路 24 手・9路 12 手）、 ヨセの境界は戦略ごとの *_endgame_move（ヨセ切替手数）で決まります。ヨセで手を緩めると相手から見て露骨に不自然なので、ヨセは最善手か「9段の人間」に任せる設計になっています。

標準の戦略（元の KaTrain から引き継いだもの）

ここに挙げる戦略は元の KaTrain にもあるもので、humanSL モデルは使いません。設定画面の説明文もそのまま読めますが、設定項目の意味と「上げる／下げる」をまとめておきます。

手加減なし ai:default

全盤サイズ設定項目なしプロ以上の強さ

KataGo の最善手をそのまま打ちます。強さは一般・エンジン設定の「分析時の最大探索手数」とモデルで決まります。分析やドットの評価は、どの戦略を選んでいてもこの「手加減なし」の KataGo が行います。

段級位相応 ai:p:rank

全盤サイズ校正済み15級〜3段

合法手の中からランダムにいくつか候補を選び、その中で最も第一感（policy）の高い手を打ちます。強い設定ほど多くの候補から選ぶので強くなります。GnuGo や Pachi などのボットで校正されており、序盤から終盤まで大ポカをしないバランスの良い弱さが特徴です。相手の強さを合わせたいときの第一候補。

設定項目既定範囲意味上げると／下げると
kyu_rank415級〜3段目標の段級位。級数を上げる（弱く）候補が減り見落としが増える。段側へ強くなる。3段は内部値 −2 に対応

Kata置碁 ai:handicap

全盤サイズ置碁向け

置き石が多い碁で、KataGo が「不利を承知で最も勝ちやすい手」を打つモードです。通常の KataGo は置碁の白番だと投げやりな手を打ちがちなので、置碁で強い相手が欲しいときはこちらを選びます。

設定項目既定範囲意味上げると／下げると
automaticONON/OFF置き石数から pda を自動で決める。OFF にすると下の pda を手で指定
pda0W+3.0〜B+3.0KataGo の playoutDoublingAdvantage（黒から見た「読みの強さの差」の仮定）。W 側へ「黒は白より読みが浅い」と仮定して、白（置碁の上手）が相手のミスを期待する勝負手を増やす（automatic なら置き石が多いほどこちら）。B 側へその逆

簡明派 ai:simple

全盤サイズ約2段

「盤面を単純にする手」を好みます。損の少なさに加えて、自分と相手の確定地が増える手・相手の手の近くに応じる手・相手の石にくっつかない手を高く評価します。重視度を負にすると逆に複雑化を目指します。一般設定の Wide root noise を上げると、強さを犠牲にこの基準により忠実になります。

設定項目既定範囲意味上げると／下げると
max_points_lost1.750〜5.0これ以上損な候補は除外（目）。上げる単純化のためにより損な手も打つ＝弱く。下げる最善手寄り

attach_penalty1−1.0〜5.0相手の石に接触する手のペナルティ。上げるツケ・ハネを避ける。負ならくっつきたがる
tenuki_penalty0.5−1.0〜5.0相手の手から縦横 3 間より離れた手のペナルティ。上げるおつきあいして応じる。負なら手抜きしたがる

難解と同じ仕組みに「罠を探す範囲の拡張」と「ΔE 床」を足した改良版です。 難解は候補手ごとに着手後の局面を解析して難解さを測りますが、従来はその候補を「損失の安い順に 7 手」しか調べていませんでした。勝勢で候補が多い手番ではリードの余剰で打てる高い手（上限 5 目の手番の 2〜5 目の手）を一度も調べておらず、実測では相手の期待損失 E が 2 目を超える罠は高い帯に多く見つかります（損失 0.3 目未満の候補で 6%、4 目超の候補で 21%）。難解＋は残りの候補から損失の範囲で等間隔に選んだ手を enigma13plus_probe_extra 手だけ追加で調べ、同じ予算の中でより大きい罠を比較に乗せます。代金の上限（損失上限・勝率フロア・勝勢時の割引）は変わりません。

もう 1 つの ΔE 床は、罠にならない外しを止める側の変更です。難解の採点 net = E ＋ 応手の見つけにくさ ＋ 自手の意外さ − 損失 は、勝勢時に損失の重みが下がると 「珍しい」だけの手が、最善手より E（相手の期待損失）が低いまま 3〜7 目払って選ばれることがありました。 実戦 13 路 7 局・外し 200 手の実測では、最善手より E を 0.2 目も多く買わない外しが 20 手あり、合計 29.6 目を払って相手の実損失から払った目数を引いた正味は −0.52 目でした（E を 0.2 目以上多く買った 90 手は +0.79 目）。

実対局の結果（13 路）: 難解 13 局と難解＋ 14 局（後半 15 局は交互に対局）を同じ方法で集計すると、相手の実損失は 1 手平均 2.25 → 3.23 目（2 目以上の失着 41% → 54%）と約 1 目増え、払った損失は 0.93 → 0.85 目で変わらず、着手時間の中央値は 0.35 → 0.40 秒でした。局ごとのばらつきに対して差は約 2σ（交互に打った 15 局だけなら 2.6σ）です。打った手の E の平均は 1.66 → 1.84 でほぼ同じなので、増えたのは「同じ代金で相手が実際に間違える量」です。9 路では難解と難解＋を交互に 11 局打っても差が出ませんでした（9 路は候補が少なく機構がほとんど働きません）。

難解＋は外し候補を「選択手の E が最善手の E を enigma13plus_min_delta_e 目以上上回る」か「検証済み損失が enigma13plus_cheap_loss 目以下」のどちらかを満たす手だけに絞り、残らなければ最善手を打ちます。 安い外し（序盤の定跡外し・最善手より良い手）は免除で残るので、変わるのは主に勝勢時の高額な外しです。同じ 7 局に当て直すと、200 手の外しのうち 15 手が最善手に戻り 22 手が別の候補に変わり、払う損失は合計 210 → 180 目、予測 E は 265 → 268 目でした。 体感では、勝勢時に「わざと数目損して珍しい手」を打つ頻度が下がり、そのぶん勝ち幅がやや大きく残ります。

詰碁用の戦略（自動で設定されるもの）

07詰碁機能

BlueStacks（Android エミュレータ）上の詰碁アプリや、Web サイトの詰碁をホットキー一発で読み取り、KaTrain 上に同じ局面を再現して AI が正解手を打つ機能です。 白の応手はアプリの盤を監視して自動で取り込まれ、正解手順は「回答帳」に記録して次回から 0 秒で再生できます。さらに ADB でアプリを操作する「自動ループ」で、出題→回答→採点→次の問題を人力ゼロで回せます。

詰碁用の外枠（F10）— 手動で詰碁を検討するとき

隅や辺に石を並べて死活問題を作ったら、「分析オプション」→「詰碁用の外枠」（F10）で盤の残りを石で埋めます。 KataGo は全局の勝率で考えるため、盤が空いていると「他の場所へ手抜きしたほうが得」と判断して詰碁を解いてくれません。外枠は「この問題を解いた側が 5 目勝つ」ように周囲の地を調整するので、AI が問題そのものに集中します。

詰碁キャプチャ（ホットキーで読み取る）

準備

  1. BlueStacks で詰碁アプリ（実測済みは「囲碁詰めチャレ」など。盤が黄色系で石のコントラストが高いアプリ）を開き、問題を表示します。Web の詰碁（PlayGo.gg 等）ならブラウザで問題を表示します。
  2. config.json の tsumego_capture.window_title（既定 "BlueStacks,Puzzle Run,PlayGo"）に、対象ウィンドウのタイトルの一部が含まれていることを確認します（カンマ区切りで複数・先勝ち）。
  3. KaTrain と対象ウィンドウを両方見える状態にします（ウィンドウが隠れていると「盤面を検出できません」になります）。

押した後に起きること

  1. 対象ウィンドウを画面キャプチャし、盤の矩形・盤サイズ（9/13/19）・各交点の石を認識します（1 秒以内）。認識に失敗するとステータス欄にエラーが出ます。
  2. 役割（黒が攻め方か守り方か）を決め、問題が小さければ死活ソルバで厳密に解き、そうでなければ枠を張って KataGo で解析します。枠は「攻め方にコウダテを与える／与えない」の両方を試し、問題を壊していないほうを自動採用します（1〜3 秒）。
  3. KaTrain のウィンドウが前面に来て、盤が拡大表示（詰碁ビュー）になり、黒番の AI が正解手を打ちます（auto_ai_black）。
  4. あなたはアプリ側で同じ手をタップします。アプリが白の応手を返すと、KaTrain がアプリの盤を監視して白の手を自動で取り込み、次の黒を打ちます（watch_white）。以降繰り返し。
正答率について 初見の問題の一次正答率は KataGo の読みに依存し、実測で約 6〜7 割です。不正解の多くは「アプリの想定とは別の正解手（別解）」や「コウ／セキの扱いの差」で、盤面に情報が無いため解析の改良では上がりません。 そこで一度間違えた問題を回答帳に記録して二度と間違えない設計になっています（下記）。同じ問題集を回すほど正答率は 100% に近づきます。

  1. 不正解だった問題をアプリの解答で確認し、KaTrain でその問題を（キャプチャし直して）開きます。
  2. 右下の「正解手順を記録」を押すと記録モードになります（帯が青「記録モード開始」）。盤をクリックして正解手順を黒白交互に打ちます。
  3. ボタンが「この手順を保存」に変わっているので押します。帯が緑「正解手順を回答帳に保存しました」になれば完了。保存先は ~/.katrain/tsumego_answers.json。

ADB（BlueStacks の HD-Adb.exe）でアプリを直接操作し、新しい問題の検知 → キャプチャ → AI の黒をアプリにタップ → 白の応手を取り込み → 正解／不正解のポップアップを画面判定 → 次の問題を自動で回します。 正解なら打った手順をそのまま回答帳へ自動記録し、不正解なら「問題を見る」→「戻す」→「ヒント」の赤丸を順にたどって正解手順を収穫し、回答帳に保存してから次へ進みます。

  • 開始／停止はどちらも Ctrl+Alt+A。開始時に ADB へ接続し、詰碁アプリが前面の BlueStacks インスタンスを自動で選びます（tsumego_autoloop.adb_serial で固定も可）。
  • BlueStacks 側で「ADB アクセス」を有効にしておく必要があります（設定 → 詳細 → Android デバッグブリッジ）。
  • 1 問 1 行の台帳が ~/.katrain/tsumego_ledger.jsonl に、失敗時のスクリーンショットが ~/.katrain/logs/autoloop/ に残ります。
  • max_problems（0＝無制限）で問題数を、max_consecutive_errors（既定 3）で連続エラー時の自動停止を決めます。
  • アプリの UI（ボタン位置・ポップアップの見た目）が変わると判定が外れます。その場合は python -m katrain.core.tsumego_autoloop probe で画面判定のしきい値を確認し直します。

Web の詰碁（PlayGo.gg など）

BlueStacks 方式で認識できない画像は、自動的に格子線検出＋座標ラベルの文字認識にフォールバックします。Web の盤は問題に合わせて盤の一部だけを表示するため、ラベル（A〜T・1〜19）を読んで絶対座標と盤サイズを確定し、実盤サイズの盤に石を配置して同じ詰碁パイプラインに流します。 19路の全体表示（4 辺すべてにラベル）は「盤面把握問題」とみなし、枠を張らずに通常の解析モードで開きます。

ログと不具合報告

08盤面監視モード（対局アプリと連動）

BlueStacks 上の囲碁対局アプリと KaTrain を並べて使い、アプリ側（相手）の着手を自動で KaTrain に取り込むモードです。KaTrain では「AI vs 人間」の対局として扱われ、アプリの相手の手が人間側の着手として入り、KaTrain の AI が応手を決めます。 AI の応手はアプリの盤の該当する交点の真上に光る輪で示されるので、あなたはそこをタップするだけです。

準備と使い方

  1. BlueStacks で対局アプリを開き、対局を始めます（空の盤でも、相手の初手が乗った盤でも可）。KaTrain と BlueStacks を両方見えるように並べます。盤の見た目は黄色い盤（囲碁クエスト系）と明るい木目盤（座標ラベル付きのアプリ）の両方に対応しており、自動で判別されます（9・13・19路）。同じタイトルの BlueStacks を 2 つ開いていると片方しか掴めないので、監視したいアプリのウィンドウだけを開いてください。
  2. KaTrain の対局者設定で片方を AI（使いたい戦略。「難解」など何でも）、もう片方を人間にしておきます。どちらの色を AI にしておいても構いません。黄色い盤のアプリでは、監視を始めるときにアプリ画面の手前（下）の対局者の石アイコンから自分の色を読み、KaTrain の AI をその色へ自動で入れ替えます（木目盤のアプリは設定どおりの色で打つので、自分の色を AI にしておきます）。新規対局を作る必要はありません（アプリの盤をそのまま取り込みます）。ルールとコミはアプリに合わせます。
  3. Ctrl+Alt+D を押します。現在のアプリの盤面を取り込んでから監視が始まり、盤の上に緑の帯「盤面監視中」が出ます。
  4. 相手（アプリ）が打つと数百ミリ秒以内に KaTrain の盤に反映され、AI が応手を決めます。応手はアプリの盤の上に色つきの輪で表示されるので、その交点をアプリでタップします。
  5. 続けて次の対局を打つときは何もしなくて構いません。監視中にアプリで次の対局が始まる（盤が空、または 2 子以内の序盤になる）と、KaTrain も自動で新しい対局に切り替わり、手前の対局者の色に合わせて AI の色も入れ替えます（黄色い盤のアプリのみ）。
  6. もう一度 Ctrl+Alt+D で監視を止めます。止め忘れても、対局が 5 分間進まなければ（アプリで投了・時間切れになった後など）監視は自動で止まり、青い帯でお知らせします。続けるときは Ctrl+Alt+D を 1 回押せば再開します。

AI 着手の強調表示

一般・エンジン設定の「AI 着手の強調表示（監視モード）」で輪の色を選べます（表示しない／シアン／マゼンタ／緑／赤／オレンジ／白）。 輪は最前面のクリック透過ウィンドウなので、アプリの操作を邪魔しません。監視の自前キャプチャからは除外されているため、輪が盤の認識を狂わせることもありません。

09盤面テーマ（盤と碁石のデザイン）

一般・エンジン設定の「盤面テーマ」ドロップダウンで、盤の木目・碁石・線の見た目を切り替えられます。同梱テーマは default / koast / lizzie / milos の 4 つ（元の KaTrain の themes に由来）。 盤の描画はその場で切り替わります。右パネルの背景色やフォントなど盤以外の部分は再起動後に反映されます。

自分でテーマを作る

  • ~/.katrain/themes/<名前>/ にフォルダを作り、theme.json（katrain/gui/theme.py の Theme クラスの属性を上書き）と、差し替えたい画像（board.png / B_stone.png / W_stone.png 等・同梱と同じファイル名）を置くと一覧に出ます。
  • 従来どおり ~/.katrain/theme*.json をベタ置きした設定は常時適用され、その上に選択テーマが重なります。
  • 地合推定の表示スタイル（TERRITORY_DISPLAY: blended / shaded / marks / blocks）や石のマーク（STONE_MARKS: all / weak / none）、色（OWNERSHIP_COLORS）もテーマで変えられます。詳細は THEMES.md。

12トラブルシューティング

症状原因と対処
起動後、右下のランプが赤いまま／「KataGo の起動に失敗」のダイアログ一般・エンジン設定の KataGo 実行ファイル・モデル・設定ファイルのパスを確認。ダイアログの「別バージョンの KataGo をダウンロード」で OpenCL 版に切り替えると動くことがあります。GPU ドライバの更新後は ~/.katrain/trtcache の再構築で初回起動が数分かかります。
Human-like 系の戦略を選んでいるのに、明らかに KataGo 最善手ばかり打つhumanSL モデルが設定されていません。一般・エンジン設定「Path to human-like model」に b18c384nbt-humanv0.bin.gz のフルパスを入れて「設定を更新」。
AI の着手が遅い（数秒〜十数秒）humanSL 系は毎手 2 回以上解析します。「分析時の最大探索手数」を下げる（1000 前後）、「難解」では先読みが効くよう相手（人間）側の考慮時間を確保する、CPU 版 KataGo なら GPU 版へ。
9 路で「狩猟戦略」がいきなりパスする狩猟は 9 路非対応で、9 路ではパスを返す仕様です。9 路では「力戦派」「持碁（9路）」「一致率追随（9路）」「難解（9路）」を使ってください。
「難解（13路）」を 9 路で選んだら普通の最善手しか打たない盤サイズ専用戦略は対応しない盤では常に最善手です。盤サイズに合った版を選んでください。
AI 設定画面に、追加したはずの項目が出ない設定画面は ~/.katrain/config.json に保存されているキーだけを表示します。「デフォルトに戻す」を押すとパッケージ既定のキーが全部書き込まれます。
設定ファイルを手で直したのに反映されないKaTrain 起動中に編集すると、終了時にアプリが設定を丸ごと書き戻して上書きします。終了してから編集してください。
F4（詰碁キャプチャ）や Ctrl+Alt+D が効かない①tsumego_capture.enabled / board_watch.enabled が true か、②他のアプリが同じグローバルホットキーを登録していないか（登録に失敗するとログに出ます）、③対象ウィンドウのタイトルが window_title に含まれているか、を確認。
キャプチャで「盤面を検出できません」対象ウィンドウが他のウィンドウに隠れている、最小化されている、盤が画面外に出ている、盤の色が想定と違う（黄色系以外）。ウィンドウを前面に出して撮り直してください。Web の詰碁は格子線とラベル（A〜T・1〜19）が見えている必要があります。
詰碁で AI が不正解を打つ役割の自動推定が外れている場合は Shift+F4（殺す）／Ctrl+F4（生きる）で撮り直し。正解手順が枠の外に出る大型問題は Shift+Ctrl+F4（枠なし）。それでも違えば正解を「回答帳」に記録すると次回から確実です。ログ ~/.katrain/logs/tsumego_*.log に判定の根拠が残ります。
盤面監視で「同期できません」の警告が続くアプリ側でパス・投了・整地が起きたか、KaTrain 側の局面とずれました。監視を止め（Ctrl+Alt+D）、必要なら手動で局面を合わせてから再度 ON にすると現在の盤を取り込み直します。
盤面監視中に相手の手が反映されないアプリの盤が KaTrain の盤と同じ手番・同じ局面から始まっているか確認。相手のパスは検出できないので KaTrain 側で手動パス。BlueStacks が別ウィンドウに隠れていると認識できません。
盤面監視がいつの間にか止まっている（青い帯）対局が 5 分間進まないと、終局後の空回り（電力・発熱）を防ぐため監視が自動で止まります。Ctrl+Alt+D を 1 回押せば再開します（アプリが次の対局に移っていればその盤を取り込みます）。止まるまでの時間は board_watch.auto_stop_sec（0 で無効）。
盤面監視で KaTrain の AI の色が入れ替わらない／逆になる黄色い盤のアプリでは、手前（下）と相手（右上）の対局者の石アイコンから色を読みます。ログの board_watch: 対局者アイコン 手前=? 相手=? で読めているか確認してください（2 つが逆の色に読めたときだけ使います）。読めないとき（木目盤のアプリ・画面レイアウトが違う）は KaTrain の対局者設定どおりの色で打ちます。KaTrain 側で AI が 0 人または 2 人だと、どの戦略を使うか決められないので開始しません。
自動ループが「ADB に接続できません」BlueStacks の設定 → 詳細 →「Android デバッグブリッジ」を ON にして BlueStacks を再起動。tsumego_autoloop.adb_path が HD-Adb.exe を指しているか確認。複数インスタンスがある場合は adb_serial（例 127.0.0.1:5585）で固定。
評価レポートの一致率が高すぎる（AI っぽい）「一致率追随（9路）」「AI一致率低減」「狩猟（一致率低減）」「難解」を使う。難解は勝勢のときほど一致率が下がり、接戦では勝ちを優先して上がります。Human-like でも「第一感ブレ」を ON にすると下がります。
対局アプリと目差が合わないルール（日本／中国）とコミをアプリに合わせてください。中国ルールでは終局時のダメ詰めや死石の取り込みで目差が動きます。

付録用語集

用語意味
KataGoKaTrain が使う囲碁 AI エンジン。局面の勝率・目差・候補手を計算します。
モデル（ニューラルネット）KataGo が局面を評価するために使う学習済みの重みファイル（.bin.gz）。通常モデルと humanSL モデルの 2 種類を使います。
humanSL モデル人間の棋譜から「この段級位の人はどこに打つか」を学習したモデル（b18c384nbt-humanv0.bin.gz）。Human-like 系の戦略の土台。
humanPolicyhumanSL モデルが出す「指定した段級位の人間がその手を打つ確率」。高いほど自然な手。本書では「人間らしさ」とも書きます。
policy（第一感）ニューラルネットが読みを入れずに出す「次の一手の確率分布」。KaTrain の「第一感」表示。
visits（探索手数）KataGo が 1 局面で読んだ手数（探索回数）。多いほど正確で遅い。候補手の下の数字（例 2.0k）はその手に費やした visits。
目（目差・scoreLead）地の差。KataGo の「推定目差」は終局時の予想。損失は「最善手と比べて何目損か」。
勝率（winrate）KataGo が推定する勝つ確率。内部では常に黒視点で計算され、表示は手番側に変換されます。
地合推定（ownership）各交点が最終的にどちらの地になるかの推定（−1＝白 〜 +1＝黒）。「未確定点」は絶対値が 0.5 未満の交点。
損失（pointsLost）ある手を打つことで最善手と比べて失う目数。ドットの色の元。
悪手フィルタHuman-like 系の戦略が「損失がしきい値を超える手は人間らしくても打たない」ようにする仕組み。序盤 2.8 目・中盤以降 5.6 目（9路 0.5 / 3.3 目）。
安全弁重み付け抽選で選ばれそうな手が 4 目以上損なら KataGo 最善手に差し替える保険（攻撃型戦略）。
一致率評価レポートの「AI の最善手との一致率」＝打った手が KataGo の最善手と同じだった割合。AI らしさの指標。
ヨセ（終盤）境界を確定させる終盤。戦略ごとの「ヨセ切替手数」以降は棋風の重み付けをやめて最善手か 9 段の第一感に戻ります。
持碁（ジゴ）目差 0 の引き分け。「Kata持碁」は僅差勝ち、「難解」の aim_jigo は持碁〜2 目以内の負けを狙います。
コウダテコウを取り返すために打つ「相手が応じざるを得ない手」。詰碁ではコウダテがある前提で正解が決まるため、KaTrain の詰碁機能もそう評価します。
セキお互いに手を出せず両方生きている形。詰碁の正解の順序は 攻め方: 無条件死 > コウ > セキ、守り方: 無条件生き > セキ > コウ。
枠（詰碁用の外枠）死活問題の周りを石で埋めて、AI が問題に集中できるようにする仕組み（F10）。
df-pn（死活ソルバ）証明数探索という手法で死活を厳密に解くプログラム。KataGo と違い「読み切れれば必ず正しい」が、大きい問題は解けない。
回答帳詰碁の正解手順を記録し、同じ問題（盤の向き違いも含む）が出たら 0 秒で再生する機能。
BlueStacks / ADBWindows 上で Android アプリを動かすエミュレータと、そのアプリをコマンドで操作する仕組み（Android Debug Bridge）。
